# 从 Vue 到 Next.js：我的前端技术迁移实践

过去几年我的主交付栈是 **Vue**：企微 SCRM（Web 以 JavaScript 为主、企微 App 用 TypeScript）、ChatAI（uni-app / Vue3）以及更早的 Vue2 后台。跳槽作品集却用 **Next.js** 来建站——这不是「抛弃 Vue」，而是一次有目的的技术迁移。

## 为什么业务里长期用 Vue

ToB SaaS 与多端产品里，Vue 生态足够成熟：

- 后台：Element Plus / 表格表单 / 权限路由，交付快
- 多端：uni-app 一套业务覆盖 H5、小程序、App
- 团队协作：Pinia、约定式目录、与后端联调路径清晰

这些经验仍然是我的主战场能力：**复杂表单、任务配置、虚拟列表、流式对话 UI**。

## 为什么个人平台选 Next.js

个人站要同时满足：

1. **可被检索**：作品集首页需要 SEO，不只是登录后的 SPA
2. **同仓全栈**：鉴权、SQLite CRUD、SSE 助手，不想拆成前后端两套仓库
3. **可部署**：`standalone` + Docker，适合自己的 VPS
4. **方向信号**：向招聘方展示我能在 React / Next 体系里独立闭环

Vue 证明「我能把业务做稳」；Next.js 作品集证明「我能选栈、建平台、上线」。

## 迁移时真正要迁移的是什么

不是把每个 `.vue` 文件机械翻译成 React，而是迁移**工程判断**：

| Vue 侧习惯     | 落到本站的做法                                           |
| -------------- | -------------------------------------------------------- |
| 页面堆逻辑     | App Router：Server 默认，动效 / 粒子下沉为 Client Island |
| 接口散落       | Route Handlers + Zod，校验与鉴权集中                     |
| 环境靠约定     | Docker / Actions / 环境变量，部署可重复                  |
| 内容写死在组件 | `src/content` 与 UI 分离，改文案不改布局                 |

## 双轨，而不是站队

我仍然会继续写 Vue 业务；本站用 Next.js，是因为作品集的产品形态更适合它。迁移的结论是：

> 用 Vue 交付复杂产品，用 Next.js 证明全栈作品集能力——两者叠加，才是我想展示的前端画像。

如果你正在从 Vue 转 React / Next，优先迁移「路由边界、数据校验、部署路径」这三块；API 语法可以后补，工程形状最值钱。
